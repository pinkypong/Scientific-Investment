1. 이 프로젝트는 무엇을 하나

VGS(Value-Growth Screener)는 미국 대형주 수백 개를 공시된 숫자로 훑어 볼 만한 후보를 고르고, 고른 종목은 사람이 정한 가정을 넣어 적정가치를 계산해 보는 도구입니다. 계산은 파이썬으로 하고, 결과는 글(리포트), 표(CSV), 그리고 화면용 파일(JSON)로 나옵니다.

같은 저장소에는 원래 반도체·메모리 4종목(삼성전자, SK하이닉스, Micron, SanDisk)을 보던 대시보드가 있고, Vercel에 배포돼 폰으로도 볼 수 있습니다. 앞으로의 방향은 VGS가 본체이고, 대시보드는 VGS 결과를 보여주는 화면으로 덧붙이는 것입니다.

2. 지키는 원칙

모든 설계 결정은 아래 여섯 가지에서 나옵니다.

원칙실제로는
추정은 누구 것이든 사실이 아니다애널리스트 추정치(EPS, 목표주가)는 점수와 가치평가 입력에 자동으로 들어가지 않고, Step 3에서 비교용으로만 봅니다. 공개 배포본에는 넣지 않고 로컬에서만 봅니다. 내 가정도 추정이므로 "가정 기반"으로 표시합니다.
사실과 가정을 나눈다공시·시장에서 관측한 값은 objective, 사람이 정한 숫자(성장률, 할인율 등)는 assumptions에 따로 둡니다.
숫자마다 출처계산에 쓰인 모든 숫자에 "공시에서 왔는지, 가정에서 왔는지" 경로가 붙습니다.
결론은 사람이엔진은 후보와 계산 결과를 보여줄 뿐 사라 팔라 하지 않습니다.
주관을 최소화사이클 해석이나 "정상 수준" 같은 판단은 엔진이 기본값으로 채우지 않고 사람이 넣습니다.
푸시는 승인 시에만작업은 로컬에 커밋하고, GitHub에는 승인받은 뒤에 올립니다.

4. 화면의 세 단계

사용자가 보는 흐름을 세 단계로 나눴습니다. 색은 앞으로 화면에서도 같은 뜻으로 씁니다.

Step 1 · 스크리닝
수백 종목을 공시 숫자로 훑어 후보를 고릅니다. 필터 기준은 사람이 조절합니다. 가정에 의존하는 값은 없습니다.
Step 2 · 종목분석
고른 종목의 10년 공시 시계열, 사람이 묶은 구간 비교, 시나리오별 가치평가를 봅니다. 가정 기반이라고 표시합니다.
Step 3 · 원문
공시·뉴스·리포트로 가는 고정 바로가기와, 애널리스트 추정치(로컬에서만)를 둡니다. 추정치는 계산에 쓰지 않습니다.

"단계"라는 말이 프로젝트 안에서 세 가지 뜻으로 쓰였기 때문에 이름을 정리했습니다. 화면은 Step 1·2·3, VGS의 데이터 수집 깔때기(전 종목 → 상위 50 → 20 → 최종 10~15)는 수집 1~4단계, 우리가 만드는 순서는 작업 A, B, C…입니다.

5. 구성 요소별 설명

VGS — value-growth-screener/ (본체)

파이썬 표준 라이브러리만 써서 따로 설치할 것이 없습니다. 수집 부분(vgs.data)은 SEC 공시를 받아 최근 4개 분기 합계(TTM), 연간(FY) 값, 그리고 최근 10년치 rolling TTM 시계열을 만듭니다. 분기가 하나라도 빠지면 그 칸은 비워 두고 짐작으로 채우지 않습니다.

엔진(engine.py)은 두 종류의 일을 합니다. 첫째, 수익성·성장·재무안정성·위험을 점수로 매깁니다. 입력은 공시 숫자지만 점수 구간과 가중치는 사람이 정한 규칙이라 "규칙 기반"이라고 부릅니다. 둘째, 사람이 넣은 가정으로 가치평가를 합니다. 방법은 네 가지입니다.

방법쉬운 설명사람이 넣는 가정
fcff (DCF)앞으로 벌 현금을 지금 가치로 할인성장률 경로, 목표 마진, 할인율(WACC)
ri (잔여이익)장부가치 + 요구수익률을 넘는 이익의 가치목표 ROE, 자기자본비용, 배당성향
epv (이익력가치)성장 없이 지금 수준의 이익이 계속될 때의 가치정상화 매출·마진, 세율, WACC — 모두 기본값 없음
상대가치PER 같은 배수로 교차 검산목표 배수

RI와 EPV는 계산에 쓴 숫자마다 출처 경로를 같이 돌려줍니다. 예를 들어 장부가치는 objective.financials.book_value(공시), 목표 ROE는 assumptions.scenarios.base.target_roe(가정)처럼 표시됩니다.

data_sources — 기존 대시보드의 수집 계층

한국(OpenDART)과 미국(SEC) 공시, 시세, 뉴스를 모아 원본 → 정규화 → 파생의 3층으로 저장하고, 대시보드 HTML에 데이터를 넣어 줍니다. 테스트가 125개 있고 GitHub CI에서 자동으로 돕니다. 업종별로 어떤 지표를 먼저 볼지 고르는 모듈(Damodaran 업종 기준점, 업종 레시피)도 여기 있습니다.

VGS와 data_sources는 지금 서로의 코드를 쓰지 않습니다. SEC 수집이 양쪽에 따로 있고, 한국 종목은 data_sources에만 있습니다. 둘을 어떻게 이을지는 열린 질문입니다.

대시보드 — 반도체_메모리_대시보드/index.html

HTML 파일 하나에 화면, 꾸밈(CSS), 동작(JavaScript), 데이터가 다 들어 있습니다. 메뉴 버튼마다 이름표(data-v="step1")가 있고, 누르면 같은 이름의 화면 하나만 켜집니다. 그래서 화면을 하나 더 만들 때 JavaScript를 고칠 필요가 없습니다.

같은 HTML이 두 벌 있습니다. 원본(반도체_메모리_대시보드/index.html)과 Vercel 배포본(web_deploy/index.html)이며, 둘은 반드시 같아야 하고 테스트가 이를 확인합니다. 저장소 맨 위의 index.html은 어디에도 쓰이지 않는 낡은 사본입니다.

6. VGS가 내보내는 파일

python -m vgs.cli export 명령이 화면이 읽을 파일을 만듭니다. 화면의 세 단계와 파일 구역이 그대로 대응합니다. 

<출력 폴더>/
├─ screen.json            Step 1 표 — 종목당 한 줄
└─ detail/<티커>.json     종목 하나의 전부 — step1 · step2 · step3
구역담긴 것성격
screen.json주가, 시가총액, 매출, 영업이익률, ROIC, 영업CF/순이익, 발생액비율, 부채/EBITDA, 이자보상배율, 매출 3년 CAGR, 매출 YoY, 영업이익률 3년 변화(12개) + 규칙 기반 점수 + 데이터 품질 플래그 수사실
step1위 숫자, 점수 구성, 데이터 품질 플래그사실
step2시나리오별 가치, 안전마진, 판정, 사람이 묶은 구간 비교, 가정 관련 경고가정
step3링크(종류, 이름, 주소)만링크
integrity계산에 쓰인 공시 숫자의 해시. 가정을 바꾸면 그대로, 공시가 바뀌면 달라짐검증용

표의 열마다 원자료 경로(예: objective.ratios.roic)가 같이 들어 있어 화면에서 숫자의 출처를 바로 보여줄 수 있습니다. 입력이 같으면 파일이 바이트까지 같고, 애널리스트 추정치는 어떤 파일에도 나가지 않습니다. Step 3 링크는 SEC 고유번호(CIK)와 이미 확인된 출처 주소로만 만들며, 뉴스나 리포트 주소를 지어내지 않습니다.

8. 결정과 그 이유

결정이유
엔진은 사이클을 해석하지 않는다사이클마다 해석 기준이 달라 고정 규칙은 오해를 만든다
EPV의 정상화 입력은 기본값 없이 사람이 넣는다"정상 수준"을 정하는 것 자체가 판단이다
점수는 "규칙 기반"이라고 표시하며 유지한다순위를 매기는 데 쓸모가 있지만 가중치는 사람이 정한 것이다
정의가 갈리는 지표는 정의 하나와 공식을 함께 기록한다숫자마다 출처 원칙
VGS가 본체, 대시보드는 덧붙이는 화면사용자 방침
Step 3은 링크만, 리포트 숫자는 가져오지 않는다애널리스트 추정치 금지 원칙
대시보드는 정적 사이트, 시세만 실시간폰과 Vercel에 가장 잘 맞고 비밀값이 브라우저로 가지 않는다
대시보드 개편은 결과 파일 형식이 정해진 뒤보여줄 데이터 없이 틀부터 바꾸면 다시 뜯게 된다
Step 1 점수는 가정 쪽 경고에 영향받지 않는다사실과 가정을 나누는 원칙. 실제 버그로 확인됨
결과 파일은 screen.json과 종목별 상세로 나눈다화면 단계와 1:1로 맞고, 같은 입력이면 같은 파일이 나온다
