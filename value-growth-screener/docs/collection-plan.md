# 토큰 절약형 Bigdata 수집 계획

## 1단계 — 전 종목 저비용 스크린

- `find_securities` 결과의 entity ID를 영구 캐시한다.
- 기업 tearsheet는 `company_overview`, `financial_ratios`, `key_metrics`만 요청한다.
- ETF는 구성 상위종목, 섹터 비중, 성과·변동성·최대낙폭·집중도만 정규화한다.
- 시장·금리·환율·섹터·팩터 스냅샷은 종목별이 아니라 배치당 한 번만 받는다.

## 2단계 — 상위 50개 후보

- `analyst_estimates`, `latest_earnings`를 추가한다.
- 추정치 변화, 현금전환, 누적·희석, 레버리지 이상 신호로 재정렬한다.
- 검색 결과는 제목·날짜·문서유형 메타데이터부터 보고 원문은 필요한 문서만 가져온다.

## 3단계 — 상위 20개 후보

- SEC 10-K/10-Q/8-K, 최신 실적 콜, RavenPack 심리, 기관 보유변화, 고용 추세를 수집한다.
- 심리는 30일 평균·변화율·이벤트 수만 저장하고 기사 전문은 보관하지 않는다.
- 보조신호는 투자 논거를 뒤집는 핵심 근거가 아니라 확인·반증 신호로만 쓴다.

## 4단계 — 최종 10~15개 후보

- SEC 원문·실적 콜·촉매를 확인하고 DCF, reverse DCF, 상대가치 교차검증을 수행한다.
- `bigdata-queue`는 순위 CSV의 상위 50/20/15개에 서로 다른 조회 묶음을 부여한다.
- 현재 미국 보유 7종목은 후보 순위와 무관하게 최종 비교용 tier 4에 강제 포함한다.
- 메타데이터·tearsheet로 판정 가능한 경우 원문 전문 호출을 생략한다.

## 캐시와 갱신

- 기업·시장·심리: 기본 24시간
- SEC 공시: 7일, 단 신규 공시 이벤트 발생 시 무효화
- 과거 재무제표: 공시 전까지 재사용
- 원문과 정규화 JSON은 분리하고 해시·관측시각·제공자를 기록한다.

## 호출 예산 원칙

1. 한 종목의 전체 tearsheet를 매번 요청하지 않는다.
2. 동일 시장 스냅샷을 여러 종목에 공유한다.
3. 1단계 탈락 종목에는 뉴스·공시·콜 원문을 요청하지 않는다.
4. 데이터가 이미 충분해 판정이 바뀌지 않으면 추가 호출을 중단한다.
